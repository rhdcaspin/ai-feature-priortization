# ROX Case Monitor

This script monitors ROX project bugs and automatically adds comments when linked Red Hat support cases are closed. It helps keep bug tracking synchronized with customer support case status.

## 🎯 **Purpose**

When ROX bugs are linked to Red Hat support cases, it's important to know when those cases are resolved. This script:

1. **Fetches all non-closed ROX bugs** from Red Hat Jira
2. **Extracts support case links** from bug descriptions and comments
3. **Checks case status** via Red Hat Customer Portal API
4. **Validates all cases**: Only adds comments when ALL linked cases for a bug are closed (not just one)
5. **Adds comments** to bugs when all linked cases are closed
6. **Tracks processed cases** to avoid duplicate comments

## 🔧 **Features**

- ✅ **Comprehensive bug scanning**: Fetches all non-closed ROX project bugs
- ✅ **Smart case detection**: Finds case links in descriptions and comments
- ✅ **Multiple link formats**: Supports various case reference patterns
- ✅ **Multiple case validation**: Only comments when ALL linked cases are closed
- ✅ **Red Hat Customer Portal integration**: Checks actual case status
- ✅ **Automatic commenting**: Adds informative comments about closed cases
- ✅ **Duplicate prevention**: Tracks processed cases to avoid spam
- ✅ **Dry run mode**: Test without making changes
- ✅ **Debug mode**: Detailed logging for troubleshooting
- ✅ **Rate limiting**: Respects API limits

## 🔄 **Multiple Case Handling**

**Important**: The script now handles bugs with multiple linked support cases intelligently:

- **Waits for ALL cases**: If a bug has multiple linked cases, the script will only add a comment when ALL cases are closed
- **No partial comments**: It won't comment if some cases are closed but others are still open
- **Comprehensive reporting**: When all cases are closed, the comment includes details about all closed cases
- **Debug visibility**: Use `--debug` to see which cases are open/closed for each bug

**Example scenarios**:
- Bug has cases `04188320` (closed) and `04188321` (open) → **No comment added yet**
- Bug has cases `04188320` (closed) and `04188321` (closed) → **Comment added about both cases**

## 📋 **Prerequisites**

1. **Python 3.6+** with `requests` library
2. **Red Hat Jira API Token** - Get from: https://issues.redhat.com/secure/ViewProfile.jspa?selectedTab=com.atlassian.pats.pats-plugin:jira-user-personal-access-tokens
3. **Red Hat Customer Portal API Token** (optional but recommended)
4. **Write permissions** to ROX project bugs in Jira

```bash
# Debug mode with limited bugs
python rox_case_monitor.py --debug --max-bugs 10

python rox_case_monitor.py --max-bugs 50
```

## 🔍 **Case Link Detection**

The script detects support case references in multiple formats:

### **Supported Patterns**
- `https://access.redhat.com/support/cases/#/case/04188320`
- `case: 04188320`
- `case #04188320`
- `support case 04188320`
- `customer case: 04188320`

### **Example Bug Content**
```
This issue is related to customer case https://access.redhat.com/support/cases/#/case/04188320
The customer reported this in support case #04188320.
See case: 04188320 for more details.
```

## 📊 **Comment Format**

When a linked case is closed, the script adds a comment like this:

```
🔔 **Linked Support Case Update**

The support case #04188320 linked to this bug has been closed.

**Case Details:**
- Status: Closed
- Summary: Compliance Operator V1.7.0 showing difference status on CLI
- Severity: Normal
- Last Modified: 2024-12-01T10:30:00Z

Please review if this bug can also be resolved or if further action is needed.

_This comment was automatically generated by ROX Case Monitor._
```

## 🗂️ **File Management**

### **Processed Cases Tracking**
The script creates `processed_cases.json` to track which cases have been processed for each bug:

```json
{
  "ROX-30293": ["04188320", "04188321"],
  "ROX-30294": ["04188322"]
}
```

This prevents duplicate comments when running the script multiple times.

## 🔧 **API Integration**

### **Red Hat Jira API**
- Uses Bearer token authentication
- Fetches bugs with JQL: `project = ROX AND issuetype = Bug AND status not in (Closed, Done, Resolved, Cancelled, Rejected)`
- Adds comments via REST API
- Includes rate limiting

### **Red Hat Customer Portal API**
- Checks case status via REST API
- Handles authentication and error cases
- Falls back gracefully if API is unavailable

## 🐛 **Troubleshooting**

### **Common Issues**

#### **Authentication Errors**
```
❌ Failed to connect to Jira: 401 Unauthorized
```
- Verify your Jira API token is correct and not expired
- Check token permissions for ROX project

#### **No Cases Found**
```
Cases found: 0
```
- Check if bugs actually contain case references
- Verify case link patterns match your format
- Use `--debug` to see what text is being searched

#### **Rate Limiting Errors (429)**
```
❌ Failed to add comment to ROX-21035: 429
```
- **Cause**: Making requests too quickly to Jira API
- **Solution 1**: Use slower rate limiting: `--rate-limit 2.0` (2 seconds between requests)
- **Solution 2**: The script now automatically retries with exponential backoff (5s, 10s, 20s)
- **Solution 3**: Process fewer bugs at once: `--max-bugs 50`

#### **Customer Portal API Issues**
```
⚠️ Red Hat Customer Portal connection test failed
```
- This might be expected if the API endpoint differs
- The script will still work but won't check actual case status
- Consider providing the correct Customer Portal API token
